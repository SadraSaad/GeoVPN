# AT-42: Windscribe Owner Acceptance Test Procedure

> **Status:** Prepared / Ready for Owner Execution  
> **Environment Note:** Per Prompt Rule 6, this acceptance procedure has **not** been executed on live hardware or against a live Windscribe subscription in the CI/subagent environment. All scripts, parsers, and test engines have been verified with synthetic fixtures and unit/integration harnesses. This document provides the exact, human-executable steps for the router owner.

---

## ۱. هدف و دامنهٔ آزمون (Objective & Scope)

این آزمون پذیرش نهایی جهت راستی‌آزمایی کارکرد جامع نسخهٔ ۱٫۱٫۰ روی یک حساب واقعی **Windscribe (Pro یا Build-a-Plan)** و روتر **Google WiFi AC-1304** (یا هر روتر تحت OpenWrt 25.12) طراحی شده است:
1. **پروتکل‌ها**: OpenVPN، WireGuard، و IKEv2.
2. **درون‌ریزی انبوه (Batch Import)**: بارگذاری هم‌زمان چندین فایل `.ovpn` و `.conf`، اعتبارسنجی نرمال‌سازی‌های خودکار Windscribe (N1 تا N5)، و اشتراک یکبارهٔ اعتبارنامه.
3. **آزمون پیش از اتصال (Pre-Connection Testing)**: اجرای آزمون‌های تک‌ردیفه و «آزمون همه» روی دستگاه موقت `gvt0` و جدول ۴۳۰۰ بدون تداخل با ترافیک محلی.
4. **تونل‌زنی تفکیکی (Split Tunneling)**: بررسی عدم نشت DNS، عبور ترافیک داخلی به صورت مستقیم و عبور ترافیک بین‌الملل از VPN.
5. **جابه‌جایی خودکار (Auto-Failover)**: سنجش بررسی سلامت دوره‌ای، آزمایش کاندیدا پیش از سوئیچ، و نرخ مجاز سوئیچ.
6. **کلید قطع (Kill Switch)**: اثبات مسدودسازی ترافیک مخصوص VPN هنگام قطعی، پایداری ترافیک مستقیم، و عدم قفل شدن دسترسی به روتر.

---

## ۲. پیش‌نیازها و دریافت فایل‌های حساب Windscribe

۱. وارد حساب کاربری خود در وب‌سایت [Windscribe.com](https://windscribe.com) شوید.
۲. به بخش **Account → Config Generators** بروید:
   - **OpenVPN**:
     - یک یا چند مکان (مثلاً Frankfurt, Zurich, Istanbul) را انتخاب کنید.
     - پروتکل: `UDP`، درگاه: `443` (یا `1194`).
     - فایل‌های `.ovpn` را دانلود کنید.
     - دکمهٔ **Get Credentials** را بزنید و نام‌کاربری و گذرواژهٔ اختصاصی OpenVPN را یادداشت کنید (این‌ها گذرواژهٔ ورود به سایت نیستند).
   - **WireGuard**:
     - یک یا چند مکان را انتخاب کنید و فایل‌های `.conf` را دانلود نمایید (کلیدهای رمزنگاری درون فایل‌ها هستند).
   - **IKEv2**:
     - بخش IKEv2 Generator را باز کنید و **نام میزبان سرور (Hostname)**، **نام‌کاربری (Username)**، و **گذرواژه (Password)** را دریافت و یادداشت کنید.
۳. اطمینان حاصل کنید که بسته‌های روتر نصب هستند:
   ```sh
   apk update
   apk add geovpn-full    # شامل هسته، LuCI، وایرگارد و strongSwan
   ```
   یا برای استفادهٔ استاندارد بدون IKEv2:
   ```sh
   apk add geovpn
   apk add geovpn-wireguard
   ```

## ۳. مراحل اجرایی آزمون پذیرش (Step-by-Step Test Procedure)

### مرحلهٔ ۱: درون‌ریزی فایل‌ها و نرمال‌سازی Windscribe (Batch Import)
۱. در مرورگر به محیط مدیریت LuCI روتر بروید: **VPN ← GeoVPN ← Connections**.
۲. روی دکمهٔ **Import** کلیک کنید:
   - تمام فایل‌های `.ovpn` و `.conf` دانلودشده را به کادر بارگذاری بکشید (Drag & Drop) یا انتخاب کنید.
   - در بخش **Shared Credentials** نام‌کاربری و گذرواژهٔ اختصاصی OpenVPN را وارد کرده و گزینهٔ **Use for all OpenVPN profiles** را فعال نگه دارید.
   - گزینهٔ پیش‌تنظیم **Preset** را روی `windscribe` قرار دهید.
   - دکمهٔ **Import All** را فشار دهید.
۳. **بررسی نتایج در LuCI**:
   - [ ] تمام پروفایل‌ها با نام تمیز (برگرفته از مکان) ایجاد شده باشند.
   - [ ] پروفایل‌های تکراری به صورت خودکار شناسایی و طبق سیاست انتخابی پالایش شده باشند.
   - [ ] برچسب ارائه‌دهنده `windscribe` به پروفایل‌ها اختصاص یافته باشد.
   - [ ] در فایل‌های WireGuard مقدار MTU به ۱۴۲۰ و keepalive به ۲۵ تنظیم شده باشد.
۴. **بررسی امنیت کلیدها از طریق SSH**:
   ```sh
   ls -la /etc/geovpn/profiles/
   ls -la /etc/geovpn/credentials/
   ```
   - [ ] دسترسی پوشه‌ها حتماً `0700` (`drwx------`) و دسترسی فایل‌های کلید و گذرواژه حتماً `0600` (`-rw-------`) باشد.
   - [ ] هیچ کلید یا رمزی در خروجی لاگ یا فایل UCI (`/etc/config/geovpn`) به صورت متنی نوشته نشده باشد.

---

### مرحلهٔ ۲: آزمون ایزولهٔ پیش از اتصال (Pre-Connection Testing)
۱. در تب **Connections** یا تب **Testing**:
   - روی دکمهٔ **Test** کنار یکی از پروفایل‌های WireGuard کلیک کنید.
   - سپس روی دکمهٔ **Test** کنار یکی از پروفایل‌های OpenVPN کلیک کنید.
   - در نهایت روی **Test All** کلیک کنید تا تمام پروفایل‌ها یکی پس از دیگری سنجیده شوند.
۲. **مشاهدهٔ رفتار**:
   - [ ] نوار پیشرفت (Progress bar) درصد تکمیل و وضعیت هر آزمون را زنده نشان دهد.
   - [ ] زمان دست‌دهی (Handshake ms) و تأخیر HTTP (Latency ms) ثبت و جدول بر اساس کمترین تأخیر مرتب شود.
   - [ ] ترافیک اینترنت جاری کلاینت‌های متصل به روتر دچار افت یا قطعی نشود.
۳. **تأیید پاک‌سازی منابع از طریق SSH**:
   ```sh
   geovpn test-cleanup --verify
   ip rule show | grep 4300
   ip link show gvt0
   ```
   - [ ] خروجی دستور تایید کند که هیچ قاعدهٔ سرگردان، جدول ۴۳۰۰ اضافی، یا کارت شبکهٔ `gvt0` باقی نمانده است (Zero Residuals).

---

### مرحلهٔ ۳: اتصال واقعی و آزمون تفکیک ترافیک (Split Tunneling Verification)
۱. یکی از پروفایل‌های قبول‌شده را با دکمهٔ **Make Active** انتخاب کرده و دکمهٔ **Start** را بزنید.
۲. پس از رسیدن وضعیت به **Connected**:
   - از یک کلاینت در شبکهٔ محلی دستورهای زیر را اجرا کنید:
     ```sh
     # سنجش IP خروجی برای ترافیک عادی (باید IP سرور Windscribe باشد):
     curl -s https://ifconfig.me ; echo
     
     # سنجش کشور خروجی:
     curl -s https://ifconfig.co/country ; echo
     ```
   - روی روتر بررسی تفکیک دامنه و IP را تست کنید:
     ```sh
     # دامنه‌ای خارج از فهرست (مثلاً google.com): باید از مسیر VPN عبور کند
     geovpn test google.com
     
     # دامنه‌ای در فهرست دور زدن (مثلاً یک سایت ایرانی مانند aparat.com یا بانک): باید DIRECT باشد
     geovpn test aparat.com
     ```
   - [ ] ترافیک خارجی از VPN و ترافیک داخلی مستقیماً از خط اینترنت محلی عبور کند.
   - [ ] بررسی نشت DNS در سایت [browserleaks.com/dns](https://browserleaks.com/dns): آدرس DNS باید مربوط به سرور Windscribe (`10.255.255.3` یا DNS سرور VPN) باشد و DNS اینترنت داخلی شما نشت نکند.

---

### مرحلهٔ ۴: آزمون جابه‌جایی خودکار (Auto-Failover Test)
۱. در LuCI به مسیر **VPN ← GeoVPN ← Auto-connect** بروید:
   - گزینهٔ **Health Checks Enabled** و **Automatic Failover** را فعال کنید.
   - در بخش **Fallback Order** دو یا سه پروفایل را به ترتیب اولویت اضافه کنید.
   - دکمهٔ **Save & Apply** را بزنید.
۲. **شبیه‌سازی قطعی**:
   - در روتر با بستن موقت ترافیک به سمت سرور VPN فعلی قطعی را شبیه‌سازی کنید:
     ```sh
     # بستن موقت پورت تونل فعال با iptables/nft
     nft insert rule inet fw4 input drop
     # یا متوقف کردن موقت پروسس VPN
     killall -STOP openvpn
     ```
   - لاگ سیستم را با `logread -e geovpn` مشاهده کنید.
۳. **بررسی رفتار سیستم**:
   - [ ] سیستم پس از رسیدن خطاهای متوالی به حد آستانه (`fail_threshold=3`) قطعی را تشخیص دهد.
   - [ ] پیش از تغییر مسیر، پروفایل جایگزین را روی جدول موقت آزمایش کند.
   - [ ] اتصال را به اولین پروفایل سالم در فهرست پشتیبان جابه‌جا کند.
   - [ ] محدودیت نرخ جابه‌جایی (حداکثر ۶ سوئیچ در ساعت و حداقل فاصلهٔ ۶۰ ثانیه) رعایت شود و سوئیچ پیاپی (Flapping) رخ ندهد.

---

### مرحلهٔ ۵: آزمون کلید قطع (Kill Switch Verification)
۱. در تب **Settings** گزینهٔ **Kill Switch** را فعال کنید و **Save & Apply** نمایید.
۲. تونل VPN را قطع کنید (**Stop** را بزنید یا اینترنت تونل را قطع کنید).
۳. **بررسی ارتباط از کلاینت شبکهٔ محلی**:
   - سعی کنید یک سایت بین‌المللی را باز کنید:
     ```sh
     curl --connect-timeout 5 https://google.com
     ```
     - [ ] ارتباط فوراً مسدود شود (Fail-Closed) و هیچ پکت رمزنگاری‌نشده‌ای از گیت‌وی عادی اینترنت خارج نشود.
   - سعی کنید یک سایت فهرست‌شده در GeoSite/GeoIP داخلی (مانند سایت‌های ایرانی) را باز کنید:
     - [ ] ترافیک مستقیم همچنان به صورت کاملاً سالم کار کند.
   - به پنل LuCI یا SSH روتر دسترسی پیدا کنید:
     - [ ] دسترسی به پنل روتر و SSH کماکان پایدار و برقرار باشد (عدم قفل شدن شبکهٔ محلی).
